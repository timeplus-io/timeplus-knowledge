Materialized views persist their processing position as checkpoints, so a restart resumes exactly where the query left off instead of reprocessing the stream.[1]
How it works
  • The pipeline periodically snapshots operator state plus the source stream sequence number.[1]
  • On recovery the engine restores the snapshot and replays from the recorded sequence — exactly-once into the view's target stream.[1]
  • The interval is tunable per view; shorter intervals trade write amplification for faster recovery.[2]
CREATE MATERIALIZED VIEW mv_orders
SETTINGS checkpoint_interval = 5
AS SELECT window_start, count() FROM tumble(orders, 5s) GROUP BY window_start;
